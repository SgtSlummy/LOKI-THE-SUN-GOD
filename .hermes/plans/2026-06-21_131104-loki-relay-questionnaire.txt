3. ORIGINAL MESSAGE HANDLING
============================

Question
--------
After Loki relays or cleans a message, what should happen to the original user message?

Why this matters
----------------
Deleting or altering original messages is destructive and can annoy users. Leaving originals in place is safest but means raw links may still be visible in source channels.

Proposed default
----------------
Phase 1:
- Leave original user messages untouched.
- Relay a cleaned embed version into the correct Loki channel.
- Do not delete originals.
- Do not suppress embeds on originals unless explicitly enabled later.

Phase 2 optional:
- For configured channels only, Loki may suppress original embeds or delete original messages after relaying.

Possible behaviors
------------------
A. Leave originals untouched.
B. Suppress Discord embeds on originals, but leave the text.
C. Delete originals after relaying.
D. Delete originals only if they contain raw URLs.
E. Replace original behavior by asking user to repost through Loki only. Not recommended.
F. Apply cleanup only in specific channels.

Important Discord constraint
----------------------------
Bots cannot edit another user's message text. They can sometimes suppress embeds if they have Manage Messages, and they can delete messages if permitted.

So if the goal is "no raw URLs anywhere," the only practical options are:
- delete originals after relaying, or
- ask users to post only through a bot workflow, or
- allow raw URLs in source channels but hide them in relay channels.

Decisions needed
----------------
1. Should Loki ever delete normal user messages?
2. If yes, should it be only in certain channels?
3. Should Loki suppress original embeds when possible?
4. Should deletion require an admin-configured opt-in per channel?
5. Should users receive a DM or notice when their message is relayed/deleted?

Your answer
-----------
Original handling mode: leave untouched / suppress embeds / delete after relay / delete only in selected channels
